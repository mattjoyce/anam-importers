anam-importers, the sources that feed Anam

Python plugins that each read one source of a person's data, shape its rows to a Facet Definition, and hand them to Anam as envelopes under their own token, so Anam holds the record and knows no vendor.

What it does not do

  • It composes no identity. An envelope names no source and no source reference. The token names the source, and Anam derives identity from the Definition.
  • It holds no token. Only anam_submit is given one, from the gateway's secret store, one instance per importer.
  • It joins nothing and summarises nothing. A weekly average is a read over facets, not a facet.
  • It keeps no state of its own. Every importer can resend everything it knows, and Anam makes an unchanged row a no-op.
  • It never retracts. When a complete resend lacks facets Anam still holds, anam_submit raises an alert and the operator decides.
  • It does not schedule itself. A gateway, or a person, decides when a plugin runs.

Core concepts

  • Anam client (anam_importer.client) A standard-library HTTP client for the five Anam calls an importer makes, with a total deadline, a response cap, no redirects, and a rule that only a whole admission receipt counts as success.
  • Envelopes (anam_importer.envelopes) Builds an envelope from a payload, checks every payload against its Definition before anything leaves, cuts envelopes into batches of at most 49, and labels a resend as snapshot parts.
  • anam_submit The one generic plugin that posts a batch event to Anam under one importer's token, after storing any documents it names and making sure Anam publishes its Definitions.
  • Shape a blood pressure export One CSV export dropped in a watched folder becomes batch events of health.blood-pressure envelopes, with the export's quirks absorbed and every payload validated before anything leaves.
  • Submit a batch A batch event emitted by any importer becomes admitted facets in Anam, with the documents stored first, the Definitions published, the receipt checked and an alert raised when a complete resend left facets absent.
  • Importers keep no state and resend everything An importer remembers nothing between runs, so every source gets a poll command that sends all it holds, and Anam's no-op on an unchanged payload makes that safe and a snapshot makes it informative.
  • A batch is at most 49 envelopes No submission carries more than 49 envelopes, and a larger one is cut, because Anam refuses it and the number decides which events share a commit.
  • Add an importer A new source is a folder with a manifest, a run.py that shapes payloads, and the Definitions it emits, plus a token line in Anam's importers file and an anam_submit instance in the gateway.

The problem

Anam is a service that keeps one person's longitudinal record as immutable facts. It deliberately reads no source itself. Something has to turn a watch database, a blood pressure app export, a CPAP card or a folder of scanned documents into the one shape Anam accepts, the envelope, and say which Facet Definition each row follows.

This repository is that something. It holds a small shared Python package (anam_importer), one generic posting plugin (anam_submit), and one plugin per source. Each importer knows exactly one vendor's file layout. Everything after the shaping is the same code for every source, so a new source costs one folder and no change to Anam.

The plugins speak the ductile plugin protocol, so a gateway can run them on a schedule or on a file event. The protocol is plain enough to run one by hand, one JSON request on stdin and one JSON response on stdout.

Who it is for

Someone who runs Anam for themselves and has data in several systems. The sources here are one person's (a Garmin watch, Withings scales, a blood pressure app, a CPAP card, a rowing logbook, a phone's location log, hand-written records), offered as working patterns for other sources. Times default to Australia/Sydney where a source writes local time.

The daemon side of the contract (the admission gate, tokens, the ledger) is described in the Anam explainer and the contract itself, docs/IMPORTERS.md section 8 in that repository.

What it does not do

  • It composes no identity. An envelope names no source and no source reference. The token names the source, and Anam derives identity from the Definition.
  • It holds no token. Only anam_submit is given one, from the gateway's secret store, one instance per importer.
  • It joins nothing and summarises nothing. A weekly average is a read over facets, not a facet.
  • It keeps no state of its own. Every importer can resend everything it knows, and Anam makes an unchanged row a no-op.
  • It never retracts. When a complete resend lacks facets Anam still holds, anam_submit raises an alert and the operator decides.
  • It does not schedule itself. A gateway, or a person, decides when a plugin runs.

Terms (17)

Anam The service this repository feeds, which keeps one person's record as append-only facts and accepts data only through envelopes posted by importers.

term

Anam is a separate project, with its own repository and its own explainer. For this repository only its edges matter. It publishes Facet Definitions, authenticates each importer by a bearer token that names a source, admits or refuses whole batches of envelopes, and reports what it still holds from a source after a snapshot.

Read the Anam explainer for the gate, the ledger and the read side. Nothing here restates them.

Asserted person The person id an envelope claims the data belongs to, set from the plugin's person_id config, or left out when the source cannot say.

term

Anam binds each envelope to the one person it records, at high assurance when the importer asserts that person and at medium when it asserts nobody. Every importer sets asserted_person from its person_id config. The Withings importer leaves it out for a measurement group the scale marked ambiguous (the reading may belong to another user of the scale), so that reading binds at medium.

Batch At most 49 envelopes sent in one request, which Anam admits whole or refuses whole in a single transaction.

term

MAX_BATCH = 49 is the largest batch Anam takes. batches cuts a list of envelopes in order. An importer emits one batch event per batch, labelled i/n so a log line says which part it was. See a batch is at most 49.

ductile A gateway that runs small plugins on schedules and events, passing each one JSON on stdin and routing the events it returns, used here to run importers.

term

ductile is a gateway (a separate project at https://github.com/mattjoyce/ductile) that runs plugins as child processes. It decides when, from a schedule or an event such as a file appearing, and routes the events a plugin returns to the next plugin through pipelines. It also holds secrets in a vault and hands a plugin only the ones its instance config names.

An importer does not need ductile to work. The plugin protocol is one JSON object in and one out, so every plugin runs from a shell. See run a plugin by hand.

Envelope The one message Anam accepts, a facet type, a Definition version and a payload, with an optional asserted person and nothing that names a source.

term

An envelope is {type, definition_version, payload} plus asserted_person when the source says whom the data belongs to. The importer builds it with envelopes. The shape is in Envelope.

It has no source and no source_ref. The token names the source, and Anam composes the identity from the Definition's identity key. An importer that tried to send either would be refused at the gate.

Where else it is used

  • mentioned by anam-importers, the sources that feed Anam, Anam, Importer
Facet One immutable fact in Anam's record, made from a payload an importer sent, with a type, an identity, a fact time and a content hash.

term

A facet is what Anam stores for an admitted envelope. Which fact it is comes from the identity key; whether it changed comes from a hash of the payload. Sending the same payload again is a no-op, and sending a different payload for the same identity supersedes the facet with a new version while the old one stays.

Importers never see a facet, only the admission receipt that says what happened to each envelope.

Facet Definition A JSON manifest that names a facet type and version, the closed JSON Schema its payload must satisfy, and how its identity and fact time are read from the payload.

term

A Definition has a meta block and a schema. meta holds facet_type, definition_version, classification, validation_mode, time_semantics.fact_time (a JSON pointer, a layout and a zone), identity_key (a list of JSON pointers) and min_binding_assurance. See Definition manifest.

An importer carries the Definitions it emits under definitions/<type>.json and validates every payload against them before anything leaves. A type Anam already bundles needs no copy in the importer, as the records importer shows. A version is immutable once Anam holds it, so a change means a new version. See add a Definition version.

Fact time The moment a fact was true in the world, read by Anam from a pointer in the payload using the Definition's layout and zone.

term

A Definition's time_semantics.fact_time names a pointer, a Go-style time layout and a zone. Anam parses the payload value with them. Importers only have to put an unambiguous time at that pointer.

Three habits show up. A source that writes UTC instants uses zone UTC (Withings dates, DreamStation starts, OwnTracks hours). A source that writes local wall-clock time names its zone and the importer attaches the same zone, read from the Definition so it is stated once (blood pressure, Garmin days). An interval source points at the interval's start.

Identity key The list of payload fields a Definition composes a facet's identity from, so an importer must send those fields and nothing else decides which fact a row is.

term

Each Definition's meta.identity_key lists JSON pointers into the payload. Anam joins their values with the source name to get the facet's identity. The key varies by type, for example /withings_id with /type for a Withings measurement, /date_excel with /reading for a blood pressure reading, /device_serial with /session for a CPAP session, and /id for most others.

An importer therefore writes the fields the key names, an ordinal or an id string, and leaves composition to Anam. The Garmin importer prefixes its ids (sleep:, steps:, day:) because the type is not part of the identity, so two types keyed on a bare date would collide. See the identity gap.

Importer A plugin that reads one source, shapes its rows to a Facet Definition, and emits batch events for anam_submit to post.

term

An importer is a folder with a manifest.yaml, a run.py and the Definitions it emits. It reads a vendor's native format, builds payloads, wraps each in an envelope, validates them locally and emits batch events. It holds no token and writes nothing to Anam itself.

The importers on master are Withings, blood pressure CSV, DreamStation, records, documents, Garmin, Concept2, OwnTracks and stays. To add one, follow add an importer.

Lookback window The number of days of recent files or messages that a handle run re-reads, set by the lookback_days key, because the source has no cursor and the importer keeps no state.

term

Garmin, Concept2, OwnTracks and stays accept a lookback_days key (defaults 3, 3, 2 and 2). A handle run reads only what changed in that window, based on file modification time or message receipt time. The window is a default, not an invariant, because how often a source syncs is the operator's fact. A poll run ignores it and reads everything.

No-op The outcome Anam gives an envelope whose payload hash matches the facet it already holds, which is what makes resending everything safe.

term

The four outcomes in a receipt are admitted, superseded, no-op and tombstoned, listed as OUTCOMES in the client. An importer cannot tell a no-op from an admission before it sends, and does not try. It sends everything the source holds and reads the counts in anam.admitted.

Records file A YAML or JSON file of facts written down from a source document by hand or by an extractor script, with the document and extraction method as provenance.

term

A records file has the top-level keys document, extracted and records. Each record names a facet type and an id, and its other fields are the payload. The records importer sends every file in a folder. One-off exports become records files through the extractors. See Records file.

Sidecar A .meta.yaml file beside a document that states the document's own date and any title or note, because the date is not in the file's bytes.

term

The documents importer refuses a file without a sidecar and names the sidecar to write. The sidecar must hold date: YYYY-MM-DD and may not declare path, sha256, bytes or media_type, which the importer measures from the file. See Sidecar file.

Snapshot A labelled set of batches that together claim to be everything a source holds of some types, letting Anam report what it holds live that the run did not carry.

term

A resend-everything run labels its batches {id, part, parts, types} with snapshot_parts. When the last part is admitted, Anam compares what it holds live from that source for those types against what the run carried. Facets it holds but the run omitted are absent. The report only informs. See an absent alert retracts nothing.

A run that could not read part of the source (a file that would not decode, a line that would not parse, a payload over the size bound) must not claim to be a snapshot, or Anam would call the unread facets absent. Every importer that can skip input drops the label in that case. See a snapshot claims everything.

Source The name Anam attributes a fact to, set by the token an importer posts under and never by the importer's payload.

term

A source is a short hyphenated name such as withings or bp-csv. Anam's importers file maps a token hash to a source and the facet types that token may write. Because identity includes the source, moving a data stream from one source name to another produces different facets, so a takeover keeps the old name when the old facets must stay the same facets.

In this repository the source is configured per anam_submit instance through token_secret, not in any importer. See one token per submit instance.

Spool A folder of JSON-lines files that the gateway's OwnTracks plugin writes, one line per message the phone posted, which two importers read and neither modifies.

term

The layout is <spool_dir>/<device>/<YYYY-MM>.jsonl. Each line is {id, body, received_at} where body is the phone's message exactly as posted, as a string. The OwnTracks importer groups location messages into hours. The stays importer reads the same spool to find stops. A last line without a newline is a write in progress and is not read yet. It knows Anam's endpoints and nothing about any source. handle reads the batch from the triggering event, and health lists the Definitions Anam publishes, which proves the URL and the token. Depends on Envelopes (anam_importer.envelopes), Definitions (anam_importer.definitions), Config helpers (anam_importer.config), Plugin protocol (anam_importer.ductile) group: importers

Source bp-csv, type health.blood-pressure v5, identity /date_excel with /reading, fact time /date_excel in Australia/Sydney. handle takes a file event with a path, poll resends every export under export_dir matching the pattern key (default BloodPressure_*).

The export is messy and the importer absorbs it without touching a value. records splits CSV the way Go's encoding/csv does with leading space trimmed. A quoted field that never closes, or holds a quote that neither closes nor doubles, makes the whole export Malformed and nothing of it is sent, because a reading swallowed into another's comment would later be reported absent. Several readings can share one timestamp, so each gets an ordinal reading within its timestamp, which is half the identity.

Depends on Envelopes (anam_importer.envelopes), Definitions (anam_importer.definitions), Config helpers (anam_importer.config), Plugin protocol (anam_importer.ductile) group: importers

Source concept2, type exercise.session v5 (the same body Garmin carries), identity /id as concept2:session:<result id>. Each payload holds the IEEE 1752 style body, with splits or intervals and every stroke beside it.

anam_documents Sends a folder of documents with sidecars as one snapshot of doc.reference envelopes, each batch naming the files whose bytes anam_submit hands to Anam's library before the envelopes go.

Source documents, type doc.reference, carried by Anam, so there is no Definition here. Identity is the folder-relative path. The payload is the sidecar's fields plus path, sha256, bytes and media_type, which the importer measures from the file and the sidecar may not declare.

Importers keep no state and resend everything An importer remembers nothing between runs, so every source gets a poll command that sends all it holds, and Anam's no-op on an unchanged payload makes that safe and a snapshot makes it informative.

decision core basis: code anam_importer/envelopes.py#snapshot_parts anchor Only a run that sends everything the source holds of types may label

Alternatives

  • Keep a cursor or a sent-set per importer, which adds state that can drift from the record and must itself be backed up and rebuilt.
  • Send only new rows and never reconcile, which cannot notice a source that dropped a fact.

Affects Envelopes (anam_importer.envelopes), Snapshot, Send a records folder, Rebuild drill (scripts/rebuild-drill.py)

Choice. Each importer has handle for a recent change and poll for everything. The idempotent commit at Anam makes resending an unchanged row a no-op, so no importer needs to know what it sent before. A poll run labels its batches with snapshot_parts, which lets Anam say what it holds from the source that the run no longer carries.

Why. It makes an importer a pure function of its source. The same property is what lets the rebuild drill build a whole ledger from the importers alone. The only recent-window state is the lookback_days key, which is a performance bound and not a cursor.

What it costs. A full resend of a large source is slow and heavy. A DreamStation card of about 1,300 sessions is 27 batches, and a network share makes reading it slow. The importers accept that cost, with handle as the cheap path where the source supports it.

Add an importer A new source is a folder with a manifest, a run.py that shapes payloads, and the Definitions it emits, plus a token line in Anam's importers file and an anam_submit instance in the gateway.

change-path core basis: docs README.md#Writing an importer anchor ## Writing an importer

Touches Envelopes (anam_importer.envelopes), Definitions (anam_importer.definitions), Config helpers (anam_importer.config), Plugin protocol (anam_importer.ductile), anam_submit, Definition manifest, Batch event, Plugin manifest, Submit a batch, An envelope names no source and no source reference, A run claims to be a snapshot only when it read everything, Config is read and checked once, at the start of a command

  1. Decide the type. If Anam bundles a Definition for it, carry none and set current_versions, as the records importer does. Otherwise write <folder>/definitions/<type>.json in the manifest format, named for the type, with a closed schema, an identity_key and a fact_time. If an external standard fits (Open mHealth, IEEE 1752), follow it and name it in source_schema.
  2. Write the folder. manifest.yaml with protocol: 2, entrypoint: run.py, the commands handle, poll and health and the events they emit, config_keys, and version equal to VERSION. run.py starts with a uv script header for jsonschema if it validates, puts the repository root on sys.path, and ends with ductile.run({...}).
  3. Shape only. Read the source, build payloads, call envelope, check and batches, and emit one anam_<plugin>.batch event per batch with envelopes, definitions (the manifest as text) and a batch label. Compose no identity and send no source.
  4. Offer a resend-everything command. poll sends all the source holds and labels the run with snapshot_parts, but only when it read everything. Raise Failure(message, retry=...) when the source fails, so the gateway knows whether another try can help.
  5. Config keys. A limit, timeout, window or pattern is a key read and range-checked through anam_importer.config at the start of each command, with its default as a constant. See add a config key.
  6. Tests. Unit tests beside the others under tests/ with invented data, a plugin run through run_plugin, and an ANAM_BIN test that admits once and resends as no-op.
  7. Token and gateway. A token whose hash goes in Anam's importers file with the source and its types, an anam_submit instance with token_secret, a trigger, and pipelines from the trigger to the importer and from <plugin>.batch to the instance. Route anam.snapshot_absent to something that tells the operator.
  8. Release. Add a changelog entry. Adding an importer is a minor version. See release a new version.
